# Navigation specification

## Global navigation

### Primary items

Use this stable order:

1. Work
2. Expertise
3. Leadership
4. About

Why this order:

- Work leads with evidence.
- Expertise makes breadth understandable.
- Leadership receives first-class status for senior positioning.
- About answers personal and career-context questions after credibility is established.

### Global actions

- Contact
- Resume

These may be visually prominent but should not compete with the four orientation destinations.

### Current-location behavior

- Clearly mark the active primary destination.
- A case study marks Work active.
- A nested leadership page marks Leadership active.
- A practice-area page marks Expertise active.
- A note does not falsely mark another section active.

## Local navigation

### Expertise

Each expertise page should expose all four practice areas as peer destinations:

- Product Experience
- Systems & Technology
- Motion & Spatial
- Strategy & Leadership

Use the same order everywhere. Do not hide them behind a hover-only interaction.

### Leadership

Recommended local topics:

- Operating principles
- Hiring & team building
- Culture & capability

Deep leadership cases may be linked contextually rather than shown as permanent subnavigation.

### Case studies

Provide:

- Return to Work
- Related case studies, selected by editorial relevance
- Linked practice areas
- Previous/next only if the order has meaning

Do not rely on an endless-scroll sequence as the only way out.

## Home-page routing

The Home page should offer multiple starting points without becoming a directory:

1. Positioning statement
2. Two or three featured outcomes or case studies
3. Four practice-area entry points
4. Leadership proposition with one evidence link
5. Brief personal context and contact action

The featured work and practice-area sections may reference the same content. Repetition is useful when each occurrence answers a different visitor question.

## Card-link rules

Every content card should make the entire card target understandable and keyboard accessible.

Card copy should answer:

- What is this?
- Why should I care?
- What was the portfolio owner's role or impact?

Avoid titles that depend on a thumbnail or confidential project name for meaning.

## Filtering and search

### Filters

Introduce filters only when the Work index becomes difficult to scan. Filters refine the current collection; they are not a substitute for editorial curation.

Rules:

- Default state shows a useful collection.
- Multiple active filters must be visible and easy to clear.
- Filtered states should be shareable by URL if implemented.
- Empty states should explain how to recover.
- On small screens, filter access must remain obvious.

### Search

Search is a later-stage utility. Add it when notes and case studies create enough volume to justify it. Search results should identify content type and offer useful excerpts.

If a conversational "ask my portfolio" interface is introduced, it is an alternate retrieval method, not the only navigation. Answers should cite public source pages on the site.

## Experimental navigation

An interactive, spatial, or 3D navigation mode may express the site's character, subject to these rules:

- Conventional links and sitemap remain available.
- Every destination has a stable URL.
- Core content is reachable without pointer precision, motion, WebGL, or JavaScript.
- The structure and labels match this specification.
- Back-button behavior and deep links work.
- Reduced-motion preferences are respected.
- The experiment does not invent a second, conflicting taxonomy.

## Footer navigation

Recommended groups:

- Explore: Work, Expertise, Leadership, About
- Connect: Contact, selected professional profiles
- Utility: Resume, Colophon, Privacy when needed
- Status: Now, only when maintained

Include a concise views-are-my-own statement if appropriate, but keep employer and confidentiality language factual and unobtrusive.

## Naming rules

- Prefer nouns for destinations: Work, Expertise, Leadership, About.
- Prefer specific outcome-oriented case-study titles over internal names.
- Use "&" only in short paired navigation labels; use "and" in URLs.
- Use "AI" where it adds meaning, not as a label on every AI-assisted project.
- Avoid "Portfolio" as a navigation item; the entire site is the portfolio.
- Avoid "Projects" if the section includes organizational and leadership cases; "Work" is broader.
